## НЕ реализовано и почему (без имитации)

1. **Накопительный эффект повторных репрессий (п. 5.8 ТЗ).** Штатная система не хранит счётчик повторных арестов/репрессий с нарастающим штрафом; такая логика живёт в Blueprint-графах и коде движка. Переопределение ассетов позволяет менять значения, но не добавлять новую логику подсчёта. Проверенный способ её реализации — только через официальный Mod Kit с редактированием Blueprint-графов; из этой среды .uasset с логикой сгенерировать невозможно. Реализация НЕ выдумана и оставлена оригинальной.
2. **Проверка выполнения обещаний по реальному приросту +5 пунктов (п. 5.3 ТЗ).** В ассетах подтверждено существование `ElectionSpeechPromiseNeededHappiness` — критерия выполнения обещания. Точная семантика этого поля (пороговое счастье или прирост) не может быть подтверждена без запуска игры, поэтому поле намеренно не изменено: неверная интерпретация сломала бы штатную проверку обещаний. Урезан только немедленный бонус (см. п. 3 в таблице), а штатные последствия невыполненных обещаний сохранены.
3. **Несколько ступеней масштаба восстаний (п. 5.7 ТЗ).** Игра уже имеет ступени (нападение партизан DA_T6GuerillaRebelAttack и восстание DA_T6GuerillaRebelUprising + современные варианты). Ускорено накопление очков до восстания, пороги не тронуты — это меняет сроки и вероятность, не добавляя новых ступеней. Боевые параметры отрядов не тронуты (запрет ТЗ).
4. **Новые предупреждения/интерфейс (п. 5.6 ТЗ).** Использованы штатные: ранние протесты (порог ×1.1), уведомления ультиматумов, предупреждение о низком мандате (BP_T6LowMandateWarning) — без новых окон и шкал, как и требует ТЗ.

## Что проверено, а что нет

### Вариант без Python (HardballPolitics.bat)

Батник повторяет весь конвейер на встроенном Windows PowerShell (без Python и без установки чего-либо). Технические отличия:

- рецепт правок встроен в сам файл (идентичен `recipe/hardball_recipe.json`);
- на Windows PowerShell 5.1 JSON обрабатывается через системный JavaScriptSerializer (он, в отличие от `ConvertFrom-Json` 5.1, не «разворачивает» одноэлементные массивы — это критично для JSON UAssetGUI); на PowerShell 7+ используется штатный `ConvertFrom/ConvertTo-Json`;
- бинарное исправление значений (hexpatch) работает по той же схеме: поиск байтов с порядковым (Ordinal) сравнением, перебор совпадений с проверкой результата;
- логика батника проверена автотестами (32 проверки, PowerShell 7): извлечение, обход узлов JSON, все 15 правил, целочисленное/дробное округление, hexpatch (включая случай дублирующихся байтов одинаковых значений), упаковка, проверка .pak, установка и удаление — на макетах инструментов, имитирующих CLI UAssetGUI и UnrealPak (включая известный баг fromjson с FloatProperty).

### Общее

Проверено в этой среде:
- логика рецепта: 15 правил, охват и запреты (автотесты `python tests/test_recipe_logic.py` — все проходят);
- корректность имён параметров: извлечены из реальных ассетов игры (см. docs/POLITICS_ASSETS_MAP_RU.md);
- механика бинарного исправления значений (hexpatch) — автотестами (Python и PowerShell);
- работоспособность URLs загрузки инструментов (UAssetGUI v1.1.0, UnrealPak) — проверена;
- команды конвейера (extract→patch→package→install) реализованы полностью, без заглушек;
- исправлен и покрыт тестами нюанс распаковки: UnrealPak извлекает файлы по пути монтирования `../../../Tropico6/Content/…`, то есть выше указанной папки — обе версии (bat и Python) это учитывают.

НЕ проверено (невозможно в этой среде, честно):
- **запуск в игре**: ни один мод не тестировался в Tropico 6, так как сборка .pak выполняется на Windows-машине с вашей копией игры;
- батник не запускался на настоящей Windows с реальными UAssetGUI.exe/UnrealPak.exe — их вызовы идентичны проверенному Python-конвейеру и подтверждены CLI-документацией UAssetGUI, но финальная проверка возможна только на вашей машине;
- фактические исходные значения параметров в вашей сборке (мод читает их при patch и пишет в журнал — проверьте журнал после сборки);
- совместимость с другими установленными модами, переопределяющими те же ассеты.

После сборки на вашем компьютере обязательно выполните проверку из docs/INGAME_TESTS_RU.md.
